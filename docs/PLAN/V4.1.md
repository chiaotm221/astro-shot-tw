# V4.1 Plan — Weather and Observing Conditions

## Goal

Add failure-tolerant forecast context that helps users decide whether observing is practical without coupling weather availability to the sky simulator.

## Phase 1 Delivery

- Fetch cloud cover, precipitation probability, humidity, visibility, wind speed, and temperature for the selected coordinates.
- Calculate a transparent planning score weighted toward cloud cover and rain.
- Show fetch/update status, cache the last successful response per approximate location, and allow manual refresh.
- Refresh automatically every ten minutes.
- Keep the simulation fully operational during API or network failure.

## Data Source

Phase 1 uses the Open-Meteo Forecast API, which exposes the required model variables without a client API key. Values are forecast-model output rather than local station observations. The interface includes attribution and makes that limitation explicit.

## Scoring

The planning score weights cloud cover 45%, precipitation 25%, visibility 15%, wind 10%, and humidity 5%. It is a product heuristic, not a meteorological safety rating.

## Follow-up

- Add an overnight hourly forecast aligned with the V3.2 timeline.
- Consider a server-side proxy only if rate control, provider credentials, or response normalization require it.
- Add severe-weather and mountain-access warnings from authoritative Taiwan sources in a separate safety-focused integration.
