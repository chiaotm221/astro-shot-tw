# V7.1 — Composition-Ready Sky Image Export

## Status

Phase 1 implemented. Standalone transparent or opaque PNG export, Full HD/QHD/
4K output choices, deterministic file naming, and background star-trail
accumulation are available without importing a photograph. Native-resolution
scene rerendering and explicit renderer-layer separation remain Phase 2 work.

## Objective

Export a useful simulated star or star-trail result image as input material for
later compositing by an external AI tool or service. The exported sky must not
require the original photograph and must preserve enough resolution and
transparency for external AI compositing workflows.

## Phase 1 Scope

- Export the current simulated star field as a standalone PNG.
- Export accumulated star trails as a standalone PNG using the selected trail
  duration and simulated time.
- Offer a transparent-background overlay and an opaque sky render.
- Export at a user-selected output size independent of the current display
  resolution, initially including 1920×1080, 2560×1440, and 3840×2160.
- Keep stars, trails, Milky Way, labels, horizon, and interface chrome on
  explicit export layers so annotations can be excluded by default.
- Preserve the selected observing place, direction, field of view, camera
  orientation, simulation time, magnitude limit, and visual settings.
- Generate files locally without uploading the source photograph or result.

## Phase 1 Implementation

- The star, Milky Way, and accumulated star-trail modes can be exported without
  an imported photograph.
- Full HD, QHD, and 4K PNG canvases are generated locally with deterministic
  mode, transparency, dimensions, and UTC timestamp file names.
- Transparent export converts dark scene pixels to zero alpha and retains
  luminous sky content for external AI compositing.
- The trail accumulation Canvas runs independently of the optional photo
  preview and is directly available to the exporter.
- AstroShot does not perform compositing, upload either image, or invoke an AI
  provider.

Phase 1 scales the live renderer snapshot into the requested output Canvas.
Phase 2 must rerender catalog objects at the target resolution and separate
stars, Milky Way, solar-system objects, labels, and horizon before the 4K detail
and explicit-layer acceptance criteria can be considered complete.

## Output Rules

- Transparent PNG contains only compositing content; untouched pixels have
  zero alpha.
- Opaque PNG matches the clean sky preview but excludes controls, selection
  markers, labels, grids, and debug overlays unless explicitly enabled.
- Export rendering uses the requested pixel dimensions directly rather than
  stretching a screenshot of the on-screen Canvas.
- Star and trail brightness remains visually stable when output resolution
  changes.
- File names include mode, simulated UTC timestamp, direction, and dimensions.

## Acceptance Criteria

- A stars-only transparent PNG can be supplied with a separate photograph to
  an external AI compositor without first removing a background color.
- A star-trail PNG reflects the selected duration and current sky orientation.
- 4K export contains materially more spatial detail than the display preview.
- Two exports with identical settings are visually deterministic.
- Export succeeds without network access and does not include UI chrome.
- Automated tests cover dimensions, alpha behavior, deterministic naming, and
  export-setting serialization; browser checks cover actual PNG download and
  compositing in Chromium.

## Non-Goals

- Physically calibrated exposure, atmospheric scattering, sensor response, or
  lens-aberration simulation.
- Deeper validation of planetary illumination, magnitude, or event timing.
- Automatic masking of trees, buildings, terrain, or foreground subjects.
- Performing image compositing inside AstroShot.
- Uploading source images or results to an AI provider.
- Automatically invoking an external AI compositing provider.
