# V1.2 Plan — Traditional Chinese Localization

## Status

Planned.

## Goal

Provide a complete Traditional Chinese interface while preserving English and
keeping translation copy centralized.

## Scope

- Add `zh-TW` as a first-class locale.
- Translate primary controls, camera modes, settings, status messages, and
  accessibility labels.
- Use Taiwan date and time formatting and clearly identify UTC+8 where needed.
- Establish consistent translation keys shared by extracted components.
- Preserve the user's locale choice without hydration mismatch.
- Review mobile layouts for longer localized strings.

## Out of Scope

- Automatic astronomical-object name translation at catalogue scale.
- Custom locations and browser geolocation.
- Recommendation, search, or information-card features.
- A third-party localization framework unless current code cannot support the
  required behavior.

## Expected Files

- `app/i18n/types.ts`
- `app/i18n/translations.ts`
- `app/site-path.ts`
- `app/SkySimulator.tsx`
- `app/CameraSystem.tsx`
- relevant components and styles

## Implementation Notes

- Audit existing Simplified Chinese copy before adding new keys.
- Keep translation values out of rendering and simulation modules.
- Use stable locale identifiers in localStorage.
- Ensure server and initial client locale selection remain deterministic.
- Do not combine localization work with rendering refactors.

## Acceptance Criteria

- Traditional Chinese and English can be selected.
- Primary user-facing text has no unintended Simplified Chinese or English
  remnants in the Traditional Chinese locale.
- Locale restoration produces no hydration warnings.
- Text does not overflow primary desktop or mobile controls.
- Canvas, WebGL, camera, and static builds behave as before.
- Type checking, lint, tests, and production build pass.
