# V5.0 Plan — Photo Import and Sky Alignment

## Status

Deferred. This plan records a future photo-processing workflow and does not
authorize implementation in the current release cycle.

## Goal

Let users select an existing landscape photograph and generate a simulated sky
or star-trail layer aligned as closely as possible to its place, time, view
direction, orientation, and field of view.

## Product Boundary

AstroShot will not open or control the device's physical camera. It will not
sample live GPS, compass, gyroscope, accelerometer, or IMU data.

The future workflow is limited to:

1. selecting an existing image file;
2. parsing available metadata locally;
3. asking the user to confirm or supply missing information;
4. generating an aligned sky or star-trail layer;
5. exporting the simulation and an alignment summary.

The current AstroShot camera remains a simulation-capture tool for saving the
sky canvas. It does not start the simulation or capture a real-world scene.

## Photo Preparation

Before importing a photo, users should follow the guidance in
`docs/USER_GUIDES/PHOTO_CAPTURE_CHECKLIST.md`.

The most useful inputs are:

- an uncropped original landscape photo;
- correct capture date, local time, and time zone;
- GPS latitude and longitude when the camera can record them;
- GPS altitude when available;
- horizontal or vertical image orientation;
- camera heading recorded separately by the user;
- focal length or 35 mm equivalent focal length;
- an unobstructed, identifiable horizon when practical.

## Metadata

Parse available EXIF locally when the selected image contains it:

- capture date and local time;
- GPS latitude and longitude;
- GPS altitude;
- image orientation;
- pixel dimensions;
- focal length and 35 mm equivalent focal length;
- camera make, model, and lens information when useful.

Metadata is optional and untrusted. Messaging apps, social networks, editors,
cloud optimization, screenshots, and exported copies may remove or rewrite
EXIF. Ordinary photo metadata often lacks reliable compass heading, pitch,
roll, and complete IMU information.

## Manual Inputs

Always allow the user to confirm or enter:

- latitude and longitude;
- approximate elevation;
- capture date, time, and time zone;
- camera direction as a compass heading from 0° to 359°;
- camera pitch relative to the horizon;
- camera roll or horizon tilt;
- horizontal or vertical orientation;
- focal length, 35 mm equivalent, or approximate field of view;
- crop and rotation applied after capture.

Missing values must not be silently invented. The UI should label estimated or
manually supplied values and explain how they affect alignment confidence.

## Normalized Input Model

```ts
interface PhotoAlignmentInput {
  fileName: string;
  widthPixels: number;
  heightPixels: number;
  capturedAt: string;
  timeZone: string;
  latitude: number;
  longitude: number;
  elevationMeters?: number;
  headingDegrees?: number;
  pitchDegrees?: number;
  rollDegrees?: number;
  focalLengthMillimeters?: number;
  focalLength35mmEquivalent?: number;
  fieldOfViewDegrees?: number;
  imageOrientation: "landscape" | "portrait";
  source: "exif" | "manual" | "mixed";
}
```

## Workflow

1. Show the photo-capture checklist before file selection.
2. Let the user select one local image.
3. Parse available metadata without uploading the image.
4. Show every extracted value and its source.
5. Request required missing values and optional alignment corrections.
6. Display the photo with draggable horizon, heading, pitch, roll, and crop
   guides.
7. Calculate the sky for the confirmed place and time.
8. Match the simulation to orientation, direction, and field of view.
9. Render point stars or a configurable star-trail layer.
10. Export the sky layer and a metadata/alignment summary.

## Star-Trail Parameters

- exposure start and end time;
- effective exposure duration;
- trail direction and angular length;
- interval gaps for stacked exposures;
- star brightness and limiting magnitude;
- lens field of view and crop;
- horizon and foreground mask preview.

## Privacy

- Process selected photos and EXIF locally by default.
- Explain clearly when a photo contains precise location metadata.
- Do not upload photos or coordinates without explicit consent.
- Do not retain the selected photo after the browser session unless requested.
- Provide an option to omit EXIF and location data from exports.

## External AI Compositing

Initial compositing remains outside AstroShot. The user can provide the original
landscape photograph and the aligned AstroShot sky to ChatGPT using
`docs/PROMPTS/CHATGPT_SKY_COMPOSITING.md`.

AstroShot should export clean inputs and must not depend on a specific AI
provider. Native masking or compositing can be evaluated later.

## Out of Scope

- Opening or controlling a physical camera.
- Live GPS, compass, motion, or IMU access.
- Continuous sensor tracking.
- Background location access.
- Remote photo storage or user accounts.
- Automatic place recognition or reverse geocoding.
- Uploading directly to an AI provider.

## Acceptance Criteria for Future Implementation

- The feature only reads an image explicitly selected by the user.
- The interface clearly distinguishes real-photo import from simulation capture.
- EXIF absence or corruption never blocks manual alignment.
- Extracted and manual values show their source and uncertainty.
- Horizontal and vertical photos are both supported.
- The simulated sky direction is reproducible from confirmed inputs.
- Star trails follow the correct celestial rotation for place, time, and view.
- No photo or precise location leaves the device without explicit consent.
- Exported images can omit EXIF and location metadata.
