# V7.2 — Photo-Metadata-Driven Simulation

## Status

Phase 2 automated implementation complete. Little- and big-endian TIFF,
malformed input, direction metadata, time-zone-aware capture instants, and
simulator application are covered. HTTPS import checks using original current
iPhone and Android photos remain the final device acceptance gate. V7.3 stays
blocked until those checks pass.

## Objective

Use metadata from an imported photograph to initialize the simulated observing
place, capture time, camera direction, and field of view. The workflow supports
creating a matching sky or star-trail image for an external AI compositor; it
does not perform image compositing inside AstroShot.

## Metadata Priority

1. Read standard JPEG EXIF fields locally in the browser.
2. Pre-fill GPS latitude, longitude, altitude, capture time, focal length,
   image orientation, and GPS image direction when present.
3. Clearly mark each value as EXIF-derived or manually entered.
4. Require user confirmation before applying the values to the simulator.
5. Preserve manual controls for missing or incorrect metadata.

## Phase 1 Implementation

- `GPSLatitude`, `GPSLongitude`, and `GPSAltitude` set the observing site.
- `DateTimeOriginal` sets the simulation instant.
- `FocalLength` or `FocalLengthIn35mmFilm` initializes the camera plan.
- TIFF orientation initializes photograph rotation.
- `GPSImgDirection` initializes camera azimuth and records whether the source
  direction is true north or magnetic north.
- Applying confirmed capture data updates the simulator location, time,
  azimuth, and altitude view without modifying the original photograph.

## Limitations

- EXIF has no universal camera pitch, roll, or full IMU-pose field. Camera tilt
  remains manually confirmed unless a future device-specific metadata adapter
  is explicitly added and tested.
- Many phones remove location or direction metadata when an image is shared or
  edited. Missing fields cannot be reconstructed reliably from pixels alone.
- Magnetic `GPSImgDirection` is retained and disclosed but is not silently
  converted to true north without a documented declination model.
- PNG, WebP, and HEIC previews remain supported, but reliable metadata parsing
  is currently limited to JPEG EXIF.

## Acceptance Criteria

- A JPEG with GPS, time, focal length, orientation, and image direction
  pre-fills all matching controls.
- Applying the confirmed values moves the simulator to the photograph's place,
  instant, and azimuth.
- Missing pose fields remain editable and do not invent an IMU reading.
- The original image and metadata remain local and unchanged.

## Phase 2 — EXIF Completion Gate

- Add binary parser fixtures that contain GPS latitude/longitude, altitude,
  `DateTimeOriginal`, focal length, orientation, `GPSImgDirection`, and its
  true/magnetic reference; do not validate direction only through constructed
  application objects.
- Verify little-endian and big-endian TIFF containers and reject truncated,
  oversized, invalid-rational, or out-of-range metadata safely.
- Preserve and disclose capture-time timezone information when
  `OffsetTimeOriginal` exists. When it is absent, label the time as local but
  timezone-unknown and require confirmation before applying it as an instant.
- Validate GPS bounds, heading normalization, supported orientation values,
  focal-length bounds, and altitude before pre-filling simulator controls.
- Test representative original files from current iPhone and Android cameras;
  keep private samples outside the repository and commit only synthetic,
  privacy-safe fixtures.
- Confirm that metadata-stripped photos present a clear manual-entry path and
  never inherit values from the previously imported photograph.
- Complete mobile-browser import and apply-flow checks over HTTPS.

## Phase 2 Implementation

- `OffsetTimeOriginal` is validated and retained so capture time can be
  converted to the correct absolute instant. A missing offset is visibly
  disclosed as local time with an unknown zone.
- GPS coordinates, altitude, focal lengths, TIFF orientation, and direction
  values are range-checked before they pre-fill controls.
- TIFF orientations 1, 3, 6, and 8 are supported in the imported-photo overlay
  and local composite preview.
- Applying confirmed metadata now updates observing place, capture instant,
  focal length, frame orientation, camera tilt, and azimuth together.
- Synthetic privacy-safe tests cover both TIFF byte orders, truncated JPEG
  input, invalid orientation, GPS direction/reference, time-zone conversion,
  and EXIF/manual provenance.

## V7.2 Exit Criteria

V7.2 is complete only when the automated fixture suite and the iPhone/Android
manual checks above pass. V7.3 sensor work remains blocked until this gate is
recorded as complete.
